# Travel-time correction model — evaluation report

Generated by running `ml_pipeline/train_travel_time.py` on 2026-09-21 against
`data/processed/travel_time_dataset.csv` (15,000 rows). This file persists the
metrics the training script prints to stdout so they are a reproducible,
citable artifact instead of only a terminal log.

## Data

- 15,000 valid OSRM/TomTom observation pairs (0 discarded for OSRM/TomTom failure).
- 150 rows (1% per transport mode) trimmed as a sanity cutoff for outliers beyond
  the app's operational range (`RECORTE_PERCENTIL = 0.99` in the training script).

## Cross-validated performance (5-fold GroupKFold, grouped by `workplace_id`)

Grouping by workplace tests generalization to commute origins not seen during
training, rather than random-split memorization.

| Model | MAE (min) | RMSE (min) | MAPE (%) | R² |
|---|---|---|---|---|
| OSRM raw estimate (no correction) | 13.52 | 16.55 | 41.3 | 0.8544 |
| Linear regression (log-time) | 9.96 | 20.92 | 25.3 | 0.7672 |
| **XGBoost (log-time)** | **3.76** | **5.49** | **11.4** | **0.9840** |

## Breakdown by transport mode (XGBoost, out-of-fold predictions)

| Mode | XGBoost MAE | XGBoost RMSE | XGBoost MAPE | XGBoost R² | OSRM-raw MAE (reference) | OSRM-raw R² (reference) |
|---|---|---|---|---|---|---|
| Driving | 5.06 | 6.59 | 16.6% | 0.7981 | 17.10 | -0.7068 |
| Cycling | 1.36 | 2.15 | 5.0% | 0.9805 | 14.00 | -0.0847 |
| Walking | 2.26 | 3.98 | 2.3% | 0.9955 | 2.30 | 0.9971 |

Walking shows the smallest gain from correction because pedestrian travel time
is largely traffic-independent, so the OSRM free-flow estimate is already close
to the TomTom-observed time. Driving and cycling — where traffic materially
changes travel time — show the largest error reduction from the learned
correction.

## Reproducibility note

The final model was re-trained on 100% of the data with the same fixed
hyperparameters and `random_state=42` used in production. `git status` shows
no diff for `ml_pipeline/model/xgboost_travel_time.json` or
`travel_time_features.pkl` after this run — the retrained model is
byte-identical to the one currently deployed, confirming these metrics
describe the model actually in production, not a different one.
